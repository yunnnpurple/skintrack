# SkinTrack — 個人保養管理與追蹤網站

SkinTrack 是一個協助使用者整理保養品、安排每日保養流程及追蹤保養習慣的網站。

## 專案目的

希望解決使用者擁有多項保養品，卻不容易管理使用時間、保養順序及每日使用紀錄的問題。

## 網站功能

1. **今日保養（Dashboard）**：顯示早晚保養清單，提供打卡功能及每日完成率。
2. **我的保養品（My Products）**：新增、編輯及刪除保養品，設定產品類型及早晚使用時間。
3. **保養紀錄（Tracker）**：顯示近七天的保養完成率與歷史打卡紀錄。

## AI 依照 AGENTS.md 擴充功能的實作示範

本次示範新增「保養品收藏數量統計」功能，讓使用者在「我的保養品」頁面直接查看目前收藏的產品總數。

開發過程遵循 `AGENTS.md` 的規範：

1. **確認現有架構**：先檢查 `index.html` 與 `js/app.js` 的功能及檔案結構。
2. **進行最小幅度修改**：在 `index.html` 新增顯示數量的元素，並在既有的 `renderProducts()` 函式中加入統計邏輯。
3. **維持設計一致性**：沿用網站原本的寶寶藍與咖啡色風格，沒有新增不必要的樣式。
4. **保留既有功能**：不修改原本的產品儲存、編輯、刪除與打卡功能。
5. **測試新功能**：確認網頁能正確顯示目前收藏的產品數量。

這次擴充證明，透過 `AGENTS.md` 訂定清楚的開發規則，AI 可以在理解既有網站架構後，持續新增功能，同時維持程式結構與設計風格的一致性。
## 使用技術

- HTML5：網頁結構
- CSS3：寶寶藍與咖啡色的響應式介面
- JavaScript：頁面互動與資料處理
- localStorage：保存使用者的保養品及打卡紀錄
- GitHub Pages：網站部署

## AGENTS.md 開發規則

本專案使用 `AGENTS.md` 定義 AI 必須遵守的開發規範，包括：

- 專案目標與主要功能
- 網站配色、排版與設計風格
- 頁面及檔案結構
- 資料格式與儲存方式
- 新增及修改功能的規則
- 功能測試與文件更新要求

未來若要新增頁面或功能，AI 必須先閱讀 `AGENTS.md`，檢查現有程式架構，再進行必要修改，避免破壞原有功能。
